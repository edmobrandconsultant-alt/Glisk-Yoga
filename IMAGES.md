## Why the Instagram photos aren't here

I could not fetch them. Instagram's `robots.txt` disallows automated access to
profile pages, and I don't route around that — so `@glisk_massage_yoga`'s images
were not downloadable programmatically.

**That's the honest answer, but it's also the right outcome**, because Instagram is
the wrong source anyway:

- Instagram re-compresses on upload and serves **1080px max**. A hero image wants
  1600px. You'd be enlarging an already-compressed file.
- Posts are cropped to square or 4:5 at upload. The original framing is gone.
- Grid photos are composed for a small square thumbnail, not for a wide web layout.

**Ask Fleur for the originals off her phone.** They will be 3–4000px, uncropped, and
dramatically better. That's a two-minute WhatsApp request that produces a better site
than any amount of scraping would have.

## Dropping new photos in

Keep the filenames. The HTML already points at them, so replacing the file is the
entire job — no markup changes needed.

```bash
./scripts/process-photo.sh ~/Downloads/IMG_4821.jpg fleur-portrait
```

That resizes, centre-crops to the right aspect ratio, strips EXIF (which matters —
phone photos carry GPS coordinates of where they were taken) and compresses to
about 82% quality.

Without imagemagick, do it by hand and hit these targets:

- `fleur-portrait.jpg` — 800×1000, 4:5
- `treatment-room.jpg` / `home-visit.jpg` — 1600×1000, 8:5
- **Under 300KB each.** There is no build pipeline resizing anything automatically,
  so a 4MB phone photo dropped in unprocessed will undo the site's main performance
  advantage over Squarespace.

Then check it: `python3 -m http.server 8000`

## Placing the two unused photos

`treatment-room.jpg` and `home-visit.jpg` exist at the right size but aren't in any
page yet — I didn't want to commit to a layout before seeing the real photographs.

Suggested placements once they arrive:

**`treatment-room.jpg` → `treatments.html`**, full-width above "At St Anne's House":

```html
<img src="/assets/img/treatment-room.jpg"
     alt="The treatment room at St Anne's House, Brislington"
     class="photo photo-wide" width="1600" height="1000" loading="lazy">
```

**`home-visit.jpg` → `home-visits.html`**, inside the "Who it suits" section or
directly under the hero, same markup with `alt="A massage couch set up in a client's
living room"`.

Available CSS classes: `.photo` (base), `.photo-portrait` (4:5), `.photo-wide` (8:5).
All use `object-fit: cover`, so a slightly-off aspect ratio crops gracefully rather
than distorting.

## Rules for any image added later

- **Always set `width` and `height` attributes.** Without them the page reflows as
  images load, which Google penalises as layout shift.
- **Always write real alt text.** Describe what's in the photo for someone who can't
  see it. Not `alt="massage"` — `alt="Fleur working on a client's shoulder"`.
- **`loading="lazy"` on anything below the fold**, never on the first image.
- **Strip EXIF before committing.** The `-strip` flag in the script does this.
  Phone photos contain GPS coordinates.
- **JPEG for photographs.** Don't convert to PNG — it will be five times the size
  for no visible benefit.
- No stock photography. It reads as stock immediately, and on a one-person business
  site it undermines the thing the site is selling, which is her specifically.

## The logo

`assets/img/logo.svg` is the only place the logo lives. The nav and the footer on
every page point at that one file, sized by CSS — so replacing the logo is a
single file swap, with no HTML to touch.

**The file currently in that slot is a stand-in.** The sun mark is right; the
GLISK lettering is set in a serif stack rather than the real lettering, which
needs the original artwork. Drop the supplied file in over the top of it, keeping
the name `logo.svg`. If what you have is a PNG rather than an SVG, save it at
about 960px wide on a transparent background, call it `logo.png`, and change the
two `src` attributes — `grep -rn 'logo.svg' *.html` finds them.
